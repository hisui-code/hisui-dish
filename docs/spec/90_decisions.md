# 90 Decisions (ADR-lite)

- YYYY-MM-DD: DB は UTC 保存に統一。表示/集計は JST 境界 →UTC 変換でクエリする。

  - 理由: サーバ/環境差異でズレない。集計の一貫性が担保できる。
  - 影響: クエリに境界変換が必要。UI 側の「今日」定義も JST 基準。

- YYYY-MM-DD: RasPi→API は REST Push。失敗時は退避 → 再送。
  - 理由: リアルタイム必須ではない。堅牢性重視。

- 2026-02-07: ユーザー管理の認可は `users.role`（`admin` / `user` / `guest`）で判定する。
  - 理由: 権限判定の責務を単純化し、管理画面のアクセス制御を明確にするため。
  - 影響: users API（一覧/更新/削除）は admin のみ許可し、非adminは 403 を返す。
  - 補足: `role` 管理は users 一覧画面で運用し、自己削除は禁止する。

- 2026-02-12: ユーザー設定編集は共通フォームをモーダルで運用し、将来の設定ページへ再利用する。
  - 理由: 現時点の更新項目が少なく、操作導線を簡潔に保ちつつ将来拡張に備えるため。
  - 影響: Users一覧の編集導線は設定モーダルへ寄せる。認可は「本人またはadmin」に統一する。
  - 補足: 将来 `/account/:userId/settings` を本線URLとして追加する場合も、同じフォームロジックを流用する。
