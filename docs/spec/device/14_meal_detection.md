# Device が食事開始 / 食事終了を判定する

## 目的

皿がある状態の重さの変化から、食事開始と食事終了を判定する。

## 入力

- `net_grams`
- 平均を取った後の `avg_grams`
- `tracking_baseline`
- `start_reference_weight`
- 時刻

## 出力

- `eat_started`
- `eat_stabilizing`
- `eat_finished`
- `eat_aborted`
- `eat_discarded`

## 処理内容

1. `net_grams` を移動平均で平滑化する
2. 待機中は `tracking_baseline` を少しずつ今の重さへ近づける
3. ただし、上方向の大きな変化はすぐ `tracking_baseline` に反映しない
4. `tracking_baseline` からの減少量を見て、開始候補に入るかを決める
5. 開始候補に入ったら、その時点より前に安定していた重さを `start_reference_weight` として固定する
6. 同時に、食事量算出用として `IDLE` 最後の安定総重量 `idle_last_weight` を保持しておく
7. `idle_last_weight` は方向別に更新条件を分ける
8. 減少方向や微小な増加は、通常の安定条件を満たせば更新する
9. 一定量を超える上方向の増加は、接触や体重乗りの可能性があるため、長めに安定しない限り更新しない
10. 長め安定を満たした上方向増加だけを、新しい `idle_last_weight` として採用する
11. `start_reference_weight` からの減少が一定量、一定時間続いたら開始確定する
12. 開始が決まったら、以後は終了判定のために安定状態だけを監視する
13. 安定した状態が `stable_duration_sec` 秒続いたら終了候補に入る
14. 終了候補に入ったあと、さらに最終安定が続いたら終了確定する
15. 終了時は、その安定区間の代表値を `finish_weight` として採用する
16. 長すぎるセッションは中断する

## なぜ必要か

- 生の重さは揺れるため、そのままでは食事開始 / 終了を決められないため
- 開始、終了、異常中断を分けて扱う必要があるため
- 食べ終わった直後の小さな揺れを吸収してから確定したいため
- 待機中の重さの中心を追う基準と、食べ始め直前の基準を分けないと誤判定しやすいため
- 食事量は一瞬の底値ではなく、終了後に戻った安定値を採った方がノイズに強いため
- 皿の置き直しや接触スパイクのあとに、待機用の基準がずれたまま開始判定すると誤検知しやすいため

## 補足

- `tracking_baseline` は待機中の重さの中心をゆっくり追うための値
- `start_reference_weight` は食事開始直前の安定した重さを固定した値
- `idle_last_weight` は食事量算出用に保持する `IDLE` 最後の安定総重量
- `finish_weight` は食事終了後に安定した総重量の代表値
- 接触スパイクの直後は、直前の安定サンプルを残したまま開始判定だけを一時停止する
- 上方向の大きな変化を受け入れた直後も、すぐには開始基準を作り直さない
- `idle_last_weight` は上方向に大きく増えたときだけ、通常より長い安定継続を要求する
- これにより、食事前に猫が皿へ一時的に体重を乗せた値を食事量基準へ採用しにくくする
- `stable_duration_sec` は、安定した状態がどれだけ続いたら終了候補に入るかを決める値
- 終了候補に入ったあとも、すぐには確定せず、最後の確認時間を置いてから `eat_finished` にする
