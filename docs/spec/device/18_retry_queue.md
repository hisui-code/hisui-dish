# Device が送信失敗分を再送する

## 目的

通信失敗時でもイベントを失わず、後で再送できるようにする。

## 入力

- 送信に失敗したキューのデータ

## 出力

- pending
- sent
- failed

## 処理内容

1. session event 用と bowl snapshot 用のキューを JSONL として保存する
2. 一定間隔で、今送れるデータを再送する
3. 成功したら sent にする
4. 失敗したら次回時刻を更新する
5. 規定回数を超えたら failed にする

## なぜ必要か

- 一時的な通信断で食事イベントを失いたくないため
- Device は常にオンラインとは限らないため

## 補足

- 2種類のキューは別々に処理する
- 再送時も、最初に作った冪等キーをそのまま使う
