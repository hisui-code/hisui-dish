# Device Thresholds

## 方針

- 閾値は実機で調整しやすい場所へ集約する
- ノイズ対策と食事判定の値を混ぜすぎない
- 1つの値に役割を持たせすぎない

## 判定値一覧

| 変数                           | 何の判定か                                       | なぜ必要か                                     |
| ------------------------------ | ------------------------------------------------ | ---------------------------------------------- |
| `START_THRESHOLD_G`            | 食事が始まったかを見るための減少量               | 小さな揺れを食事開始と勘違いしないため         |
| `START_CONFIRM_SECONDS`        | 食事開始候補がどれだけ続いたか                   | 一瞬だけ下がった時に食事開始と決めないため     |
| `STABILITY_EPSILON_G`          | どこまでを安定とみなすか                         | 終了判定で小さな揺れを許容するため             |
| `END_STABLE_SECONDS`           | 安定がどれだけ続いたら終了候補に入るか           | 一時的に止まっただけで終了にしないため         |
| `FINALIZE_SECONDS`             | 終了候補に入ってから、さらにどれだけ待つか       | 終了直前の小さな動きを吸収するため             |
| `MAX_SESSION_SECONDS`          | 長すぎる計測をいつ中断するか                     | 異常時にセッションが終わらなくなるのを防ぐため |
| `MIN_CONSUMED_G`               | 何g未満なら食事量として使わないか                | 小さすぎる差をノイズとして捨てるため           |
| `MOVING_AVG_WINDOW`            | 平均を取るサンプル数                             | 重さの揺れをならして判定を安定させるため       |
| `MAX_VALID_NET_JUMP_G`         | 急に大きく変わった値をどこで除外するか           | おかしな値をそのまま判定に使わないため         |
| `JUMP_ACCEPT_SECONDS`          | 大きな変化を新しい基準として受け入れるまでの時間 | 単発ノイズと継続する変化を分けるため           |
| `BOWL_PRESENT_THRESHOLD_G`     | 皿ありとみなす重さ                               | 皿がある時だけ食事判定を動かすため             |
| `BOWL_PRESENT_CONFIRM_SECONDS` | 皿ありと決めるまでの時間                         | 皿を置く途中で誤って判定しないため             |
| `BOWL_ABSENT_THRESHOLD_G`      | 皿なしへ戻す重さ                                 | 皿を外したあとに食事判定を止めるため           |
| `BOWL_ABSENT_CONFIRM_SECONDS`  | 皿なしと決めるまでの時間                         | 一瞬の持ち上がりで皿なしにしないため           |

## 各値の詳細

### `START_THRESHOLD_G`

何の判定か:

- baseline からどれだけ減ったら、食事開始候補とみなすかを決める

なぜ必要か:

- センサー値はいつも少し揺れるため、少し減っただけでは食事と判断できない
- しきい値を設けないと、静止中のノイズでも開始してしまう

### `START_CONFIRM_SECONDS`

何の判定か:

- 開始候補がどれだけ続いたら `eat_started` と決めるかを決める

なぜ必要か:

- 一瞬だけ下がった値をそのまま開始とすると誤検知しやすい
- 「減った状態が続いている」ことを確認してから開始したい

### `STABILITY_EPSILON_G`

何の判定か:

- 直前の値との差がどこまでなら安定とみなせるかを決める

なぜ必要か:

- 終了判定では、細かい揺れを許容しないと永遠に安定しない
- 逆に大きすぎると、まだ食事中なのに安定とみなしてしまう

### `END_STABLE_SECONDS`

何の判定か:

- 安定した状態がどれだけ続いたら終了候補へ進むかを決める

なぜ必要か:

- 一時的に動きが止まっただけの状態を終了扱いしないため
- 食事が実際に終わったと言える長さを持たせたい

### `FINALIZE_SECONDS`

何の判定か:

- 終了候補に入ったあと、さらにどれだけ安定したら本当に終了とするかを決める

なぜ必要か:

- 終了直前にもう一度食べる、皿に触る、といったケースを吸収したい
- 終了候補と終了確定を分けることで、終了判定を急ぎすぎないようにする

### `MAX_SESSION_SECONDS`

何の判定か:

- セッションが最大何秒続いたら異常として止めるかを決める

なぜ必要か:

- センサー異常や基準崩れで状態が戻らない場合の保険が必要
- 無限に `MEASURING` が続く状態を避けたい

### `MIN_CONSUMED_G`

何の判定か:

- 何g未満なら食事量として使わずに捨てるかを決める

なぜ必要か:

- 微小差分までイベント化するとログがノイズで埋まる
- 本当に意味のある食事だけを保存したい

### `MOVING_AVG_WINDOW`

何の判定か:

- 平均を取るのに何個の値を使うかを決める

なぜ必要か:

- 生の重量値は揺れるので、そのまま判定に使うと不安定になる
- 窓が大きいほど滑らかになるが、開始や終了の反応は遅くなる

### `MAX_VALID_NET_JUMP_G`

何の判定か:

- 直前の有効な値との差がどれだけ大きいと、おかしな急変とみなすかを決める

なぜ必要か:

- 配線ノイズや読み取りグリッチをそのまま状態機械へ流したくない
- ただし小さすぎると、実際の皿の着脱もずっと弾いてしまう

### `JUMP_ACCEPT_SECONDS`

何の判定か:

- 上方向の大きな変化がどれだけ続いたら「新しい基準」として受け入れるかを決める

なぜ必要か:

- 皿を置き直した直後は大きな jump が出る
- 単発ノイズは弾きたいが、継続する環境変化は受け入れないと復帰できない

### `BOWL_PRESENT_THRESHOLD_G`

何の判定か:

- 皿が乗っているとみなすための重さの下限を決める

なぜ必要か:

- 皿が無い状態まで食事判定すると、着脱と食事量の減少が混ざる
- 皿あり時だけ食事状態機械を動かしたい

### `BOWL_PRESENT_CONFIRM_SECONDS`

何の判定か:

- 皿ありの重さがどれだけ続いたら `NO_BOWL` から `IDLE` へ入るかを決める

なぜ必要か:

- 皿を置く途中の一瞬の通過値で present に入ると不安定になる
- 継続して乗っていることを確認してから開始したい

### `BOWL_ABSENT_THRESHOLD_G`

何の判定か:

- 皿なしへ戻すための重さの上限を決める

なぜ必要か:

- 皿が外れたあとも present のままだと、古い baseline を引きずる
- present と absent で閾値を分けることで、境界付近の揺れを吸収できる

### `BOWL_ABSENT_CONFIRM_SECONDS`

何の判定か:

- 皿なしの重さがどれだけ続いたら `NO_BOWL` へ戻るかを決める

なぜ必要か:

- 一瞬だけ皿が浮いた、手が当たった、といった揺れで absent に戻したくない
- 皿が本当に外れたことを確認してから履歴を捨てたい

## 調整方法

- 開始が遅いなら `MOVING_AVG_WINDOW` と `START_CONFIRM_SECONDS` を見る
- ノイズで開始しやすいなら `START_THRESHOLD_G` と `MIN_CONSUMED_G` を見る
- 終了が遅い、または早すぎるなら `STABILITY_EPSILON_G` `END_STABLE_SECONDS` `FINALIZE_SECONDS` を見る
- 皿の着脱で詰まるなら `BOWL_*` と `JUMP_ACCEPT_SECONDS` を見る

## 調整パターン

### 食事開始が遅い

起きること:

- 実際には食べているのに `eat_started` がなかなか出ない
- 食事量が実際より少なく出やすい

まず見る値:

- `MOVING_AVG_WINDOW`
- `START_CONFIRM_SECONDS`
- `START_THRESHOLD_G`

考え方:

- 平均を取る数が多すぎると、反応が遅くなる
- 開始確認の時間が長すぎると、開始確定が遅くなる
- 開始に必要な減少量が大きすぎると、食べ始めを拾いにくい

### 食事開始が早すぎる

起きること:

- 食べていないのに `eat_started` が出る
- 軽い接触や揺れを食事と勘違いする

まず見る値:

- `START_THRESHOLD_G`
- `START_CONFIRM_SECONDS`
- `MIN_CONSUMED_G`

考え方:

- 開始に必要な減少量を少し大きくする
- 開始確認の時間を少し長くする
- 小さすぎる食事量を破棄する値も合わせて見る

### 食事量が少なく出る

起きること:

- 実際より小さい `eaten_grams` が出る

まず見る値:

- `MOVING_AVG_WINDOW`
- `START_CONFIRM_SECONDS`
- `START_THRESHOLD_G`

考え方:

- 開始判定が遅いと、減った後の重さを基準にしてしまう
- まずは開始を早く拾える方向を試す

### 食事量が大きく出る

起きること:

- 実際より大きい `eaten_grams` が出る
- 食べる前の揺れまで食事量に入ってしまう

まず見る値:

- `START_THRESHOLD_G`
- `START_CONFIRM_SECONDS`
- `MOVING_AVG_WINDOW`

考え方:

- 開始判定が早すぎると、食べる前の揺れを基準に入れやすい
- まずは開始条件を少し厳しくして様子を見る

### 終了が遅い

起きること:

- 食べ終わっても `eat_finished` まで時間がかかる

まず見る値:

- `STABILITY_EPSILON_G`
- `END_STABLE_SECONDS`
- `FINALIZE_SECONDS`

考え方:

- 安定とみなす幅が狭すぎると、いつまでも終了候補に入れない
- 安定時間や最終確認時間が長すぎても終了が遅くなる

### 終了が早すぎる

起きること:

- まだ食べているのに `eat_finished` が出る
- 少し止まっただけで終了扱いになる

まず見る値:

- `STABILITY_EPSILON_G`
- `END_STABLE_SECONDS`
- `FINALIZE_SECONDS`

考え方:

- 安定とみなす幅が広すぎると、まだ変化中でも安定扱いになる
- 安定時間や最終確認時間が短すぎると終了が早くなる

### 皿を置いても復帰しない

起きること:

- 皿を置いたあとも `NO_BOWL` のままになる
- 重さが変わっているのに待機状態へ入れない

まず見る値:

- `BOWL_PRESENT_THRESHOLD_G`
- `BOWL_PRESENT_CONFIRM_SECONDS`
- `JUMP_ACCEPT_SECONDS`

考え方:

- 皿ありとみなす重さが高すぎると present に入れない
- 確認時間が長すぎると present へ切り替わりにくい
- 大きな変化を新しい基準として受け入れるまでが長すぎる場合もある

### 皿を外しても復帰しない

起きること:

- 皿を外したあとも皿あり状態のままになる

まず見る値:

- `BOWL_ABSENT_THRESHOLD_G`
- `BOWL_ABSENT_CONFIRM_SECONDS`

考え方:

- 皿なしとみなす重さが低すぎると absent に戻れない
- 確認時間が長すぎると切り替わりが遅くなる

### 皿の置き直しで詰まる

起きること:

- 一度大きく重さが変わったあと、判定が止まったように見える

まず見る値:

- `MAX_VALID_NET_JUMP_G`
- `JUMP_ACCEPT_SECONDS`

考え方:

- 急な変化を除外する幅が小さすぎると、ずっと無視し続けやすい
- ただし広げすぎると、本当におかしな値まで通してしまう

### ノイズが多い

起きること:

- 値がふらつく
- 開始や終了が不安定になる

まず見る値:

- `MOVING_AVG_WINDOW`
- `STABILITY_EPSILON_G`
- `MIN_CONSUMED_G`
- `MAX_VALID_NET_JUMP_G`

考え方:

- まずは平均を取る数を見直す
- 小さい揺れをどこまで許すかを見直す
- 微小差分を捨てる値も合わせて見る
