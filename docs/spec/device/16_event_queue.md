# Device がイベントと残量をキューへ積む

## 目的

食事イベントと皿の残量を、あとで送りやすい形でキューへ積む。

## 入力

- 食事判定の結果
- 今の food 重量

## 出力

- session event のキュー
- bowl snapshot のキュー

## 処理内容

1. 状態機械が返したイベントをローカルファイルへ追記する
2. `eat_finished` だけを session event としてキューへ積む
3. 食事終了時の残量を bowl snapshot としてキューへ積む
4. IDLE 中は定期的に bowl snapshot を積む
5. 前回との差分が小さい場合は snapshot を送らない
6. queue の HTTP送信で一時的な通信失敗が起きた場合は、送信関数の中で短い再試行を行う
7. それでも失敗した場合だけ queue 側の次回再送スケジュールへ渡す

## なぜ必要か

- 食事イベントと残量の記録は用途が違うため
- 送る前に一度 Device の中で持っておくと、失敗時にやり直しやすいため
- 送信前の時点でも、何が起きたかを Device 側で追えるようにしたいため
- 食事終了時だけでなく、補充だけ起きた時にも残量を更新したいため

## 補足

- session event 用のキューと bowl snapshot 用のキューは分けて持つ
- `eat_started` など途中イベントは API 送信用キューには積まない
- 通信 retry と queue 再送は責務を分ける
- 短い通信断は送信関数側で吸収し、長引く失敗だけを queue の再送管理で扱う
